# Testing and verification (contributor guide)

This is the deep-dive companion to the [Testing and verification](../README.md#testing-and-verification) section of the main README. It explains how each verification gate is built, what its corpus covers, and what it has caught. Run every gate from the repository root.

Here is how it fits together. Every device has an **independent reference model** in `tools/*_ref.luau`, written separately from the core. The **differential gates** run the core and its reference on byte-identical inputs and compare every observable output. Two engines that agree can still both be wrong, so **oracle phases** pin specific rules against literal expected values: colors, words, register values, tick counts. A shared transcription typo then fails somewhere. A separate constant-drift gate keeps the constant tables honest, and the headless boot check covers the one thing no unit test can, which is the full BIOS to CD to gameplay handoff.

## Headless boot check

The primary regression gate (quick run instructions are in the [main README](../README.md#headless-boot-check)). Run it after any change to timing, CPU, DMA, or the BIOS path, because on a PS1 a timer change can become a CD bug several minutes later. It reports PASS/FAIL from independent evidence streams (CD-ROM MMIO activity, GPU frame flips, PC advancement, pad setup, main-loop clusters, input acceptance) and prints EVIDENCE and BLOCKER lines for each one. Treat those lines as the diagnostic: PASS needs the full BIOS, CD, and pad path to light up, and a short window can end in FAIL before the BIOS even reaches the disc. See *The boot check prints FAIL* in the [main README FAQ](../README.md#the-boot-check-prints-fail-is-the-emulator-broken) for how to read a FAIL.

## CPU harness

[`src/shared/PS1/Harness.luau`](../src/shared/PS1/Harness.luau) loads a built-in base64 test executable (for example `AccessTime`), runs it under an instruction budget, detects stagnant PC loops, and reports pass / budget-exhausted / stopped with register and COP0 dumps. Run it in Roblox via `shared.PS1RunCpuTestAndPrint()` or the `PS1RunCpuTestRemote` remote.

## Independent reference models

`tools/*_ref.luau` covers CPU, memory, GPU, GTE, CD-ROM, DMA, MDEC, SPU, XA, timers, interrupts, pads, and memory cards. These are written separately from the runtime, so differential checks never compare a function against itself.

## Reference-model drift check (refcheck)

`lune run tools/run.luau refcheck` compares every named constant the core and its reference model both declare, in either `local` or module-table form, and fails on any value disagreement. A pair with zero shared names is reported as an unguarded comparison and fails too, so coverage can never silently shrink to nothing (currently 105 shared constants in agreement across all 9 pairs, including the memory bus map). This guards the cheap factual layer of the differential promise.

## Deep CPU differential (cpudiff)

`lune run tools/run.luau cpudiff` feeds a curated corpus of hand-assembled programs into three engines: the core's canonical single-step path, the core's block-cache interpreter (what the runtime uses at speed), and the reference model. Each runs against a fresh RAM-only bus, and every observable CPU field (gpr 0-31, hi/lo, all modeled COP0 registers, pc) is compared after every instruction. The two core engines share the decode table but execute through separate code paths, so the gate covers drift between them as well as drift of either from the reference.

- **Corpus coverage**: ALU signs and shifts, overflow exceptions, the DIV/DIVU special cases and divide-by-zero results, every branch direction with delay slots, JAL/JALR/JR linking, COP0 write masks and RFE, syscall/break/address-error/RI exceptions with their vectors and cause bits, and byte/half/word plus unaligned `LWL`/`LWR`/`SWL`/`SWR` access with the load-delay hazard.
- **Interrupt delivery and its IE gate**: two programs enable irq line 0 through the shim's interrupt-controller lane and arm a harness-side device line that asserts at an instruction boundary. One dispatches immediately, with the preempted instruction in `epc`, ip2 set in `cause`, and the status mode stack pushed. The other proves a pending line does not dispatch while `iec` is clear, then dispatches at the first enabled boundary.
- **Self-modifying code**: one program overwrites an instruction inside an already-cached block and jumps back into it, so the block engine's write-invalidation lifecycle (page-version stamp bumped on store, re-decode on re-entry) is exercised rather than running every block cold. The reference fetches the patched word from shared memory, so a stale cache diverges from it on the first step back.
- **Completion invariant**: every program must run to completion. Each non-raising program executes all of its words, and each of the ten exception programs must end at the exception vector. A program that stops early is an UNDERRAN failure, because the per-step comparison only sees instructions that actually executed.
- **After-oracles**: selected programs declare an absolute after-oracle that pins concrete final register and cop0 values on each engine independently. The differential alone cannot see a semantic bug shared by all three engines. That blind spot is how a no-op `rfe` word and a cu0-less readback that raised the same CpU in every engine each passed as "agreed" in earlier rounds.
- **Encoding self-test**: before the corpus runs, pins 54 instruction words plus two whole label/branch/jump programs to their exact encodings. The differential cannot see a shared mis-encoding, because all three engines execute whatever word the assembler emits and agree on it. That blind spot is exactly how an `rfe` that assembled to a no-op `mfhi` slipped through a full-state gate in an earlier round, so an encoding regression now fails the gate before the corpus starts.
- **Decoder fuzz**: after the corpus, runs words the hand assembler cannot emit: deterministic sweeps over the small decode fields (all 64 special functs, all 32 regimm rt lanes, every cop0 register and command lane, cop1/2/3 sub-ops) plus uniform-random streams, each compared per instruction across the same three engines. Decode drift on any word the assembler never produces is invisible to the corpus, and the fuzz has already caught real disagreements settled against the ps1-tests hardware suite. Unknown cop0 rs lanes no-op instead of raising RI, and cop1/cop3 plus `lwc0-3`/`swc0-3` raise a coprocessor-unusable exception with `ce` = the cop number when their cu bit is clear, in kernel mode too. The BIOS's own `atof`/`strtod` lock up exactly this way on hardware.
- **Store comparison**: beyond CPU state, compares the stores each engine performed on every instruction (address, width, and value). The engines share a bus, so a wrong store is silently overwritten by the other side's own store before any read sees it, which means CPU-state agreement alone could never catch a store bug. A store-everything-plus-one mutation passed all 9,520 fuzz instructions and every corpus program except the one oracle that happened to read code back.
- **Status**: currently 20 programs in agreement. A failure anywhere in the corpus, the encoding pins, or the fuzz names the program, engine, step, instruction, and field and exits nonzero.

## Checkpoint round-trips

[`src/shared/PS1/Ckpt.luau`](../src/shared/PS1/Ckpt.luau) defines the versioned binary snapshot format (`PS1CKPT1`, currently v15), which covers CPU pipeline state, RAM, VRAM, device FIFOs, CD drive timing, SPU voice state, timer gates, DMA registers, controller transactions, and memory-card state. Resuming to a known game state is a regression gate, though a checkpoint is not a compatibility guarantee for arbitrary old snapshots. No capture script is committed. A snapshot is taken ad hoc with `Ckpt.save(runtime, path, fs.writeFile)` once the runtime has reached the state you want. The `runtime` handle comes from the shared boot helper in [`tools/lib/boot.luau`](../tools/lib/boot.luau).

## GTE execution differential (gtediff)

`lune run tools/run.luau gtediff` seeds byte-identical register state into the core GTE and its reference model and feeds both the same cop2 command words, comparing all 32 data and 32 control registers after every executed command. This exists because cop2 instructions inside cpudiff run both engines against a single shared GTE instance, so a bug inside GTE itself would agree by construction. The constant layer was guarded by refcheck, but no execution feed existed.

- **Command phase**: a fixed-seed xorshift drives random single-command cases per data op (fresh state, random mode bits) plus long consecutive-op streams with carried state for the sticky flag register and mac-accumulating ops. Currently about 15,000 commands are in agreement.
- **Register-transfer phase**: drives the transfer surface (`writeData`/`writeCtrl` and `readData`/`readCtrl` over every register with boundary values, plus sxyp fifo push chains and irgb/lzcs probes). cpudiff runs both CPUs against a single shared GTE, and the array-seeded command phases bypass the transfer methods entirely, so the extension rules, fifo push-on-write, irgb 555 decode, and lzcs side write had no gate. Currently about 1,100 transfers are in agreement.
- **Found divergence**: on first run, the reference model's multi-vertex color ops (NCDT, NCT, NCCT) never pushed the RGB fifo, while the core pushes once per vertex pass as hardware does. The reference was fixed to match, and all 22 data ops now agree.
- **Status**: a divergence names the op, case, command, and register and exits nonzero.

## GPU state-machine differential (gpudiff)

`lune run tools/run.luau gpudiff` feeds byte-identical GP0 and GP1 word streams to the core GPU and its standalone reference model. After every settled command it compares exactly the VRAM words the engines wrote (each engine logs its writes, so the comparison is exact and incremental instead of re-hashing the full 524,288-word VRAM after every command; a one-time full-VRAM sweep at the end proves the logs missed nothing), the CLUT cache, the static GPU status bits, draw mode, texture palette, drawing area and offset, the texture-disable masks, and every word returned by VRAM-to-CPU reads. The reference model existed but nothing ever executed it, and the CPU differentials stop before the GPU, so this is the first gate that runs the two GPUs against each other.

- **Coverage**: a scripted corpus over every command class (fills, mono and shaded textured polygons and quads, all rectangle size classes, mono and gouraud lines and terminated polylines, all three transfer directions with overlap, mask bits, texture windows, CLUT cache clears), a GP1 sweep over every command code with boundary parameters, and a fixed-seed fuzz of 90 random config plus command sequences.
- **Early divergences (fixed)**: first runs found real bugs settled against psx-spx, the PSX SDK structs, and DuckStation. The reference missed GP0 0x01 CLUT-cache invalidation, mapped GP1 0x08 display-mode bits onto the wrong status bits, re-read cells its own oversized VRAM copy had already overwritten, and mislabeled the line opcode family. The correct labels: 0x44-0x47 are mono lines and 0x50-0x57 gouraud lines, not the reverse; only 0x48-0x4F and 0x58-0x5F are polylines. The core parsed gouraud polylines color-led on the wire, although the SDK and psx-spx both say they are vertex-led, and its GP1 0x08 bit 16 mapping and reverse-bit position disagreed with the reference. The reference was fixed where it contradicted DuckStation, and the core was fixed where it contradicted the wire format and DuckStation. Both now agree on every generated stream.
- **Completion invariant**: every config preamble and command must leave both engines back at a command boundary. This exists because the fuzz generators shipped three silent stream-malformation bugs that per-word settling could not see. One was a vertex count written as `quad and 4 or 3`, where quad is a raw 0 or 1 bit and 0 is truthy in Lua, so every triangle opcode received a quad-sized word stream. One was a transparency value drawn from two bits that bled into the texture bit and changed the decoder's expected word count. One was a rectangle size drawn as a bit test that shifted opcodes out of rectangle space. All three emitted trailing words that the decoders re-interpreted as new commands, and the fuzz passed until a random collision surfaced as an unrelated-looking divergence two hundred words later. Each malformation now fails at its own command boundary with attribution, and a GP0 word-count mutation in the core fails the corpus at the first fill.

### Oracles

Two engines that agree can share the same bug, so each oracle pins a rule against literal expectations. Sixteen are in place.

1. **Dithering rules**: an audit against DuckStation found a shared bug the differential structurally cannot see. Both models dithered every primitive whenever the draw-mode dither bit was set, while DuckStation disables dithering for rectangles and for flat or raw-textured polygons. Only lines, shaded polygons, and modulated-textured polygons dither, so a flat fill or sprite drawn with the dither bit on rendered as per-pixel noise instead of a flat color. Both models were fixed to compute dither enable per primitive, and the oracle draws fills, flat triangles, and mono/raw/modulated rectangles with the dither bit set and asserts literal expected colors at every pixel. Reverting the rule in both engines at once passes every engine-vs-engine compare and fails only the oracle. A pixel that must read `0x1999` flat comes out `0x1598` dithered. That is the point: engine agreement cannot pin a rule the reference model itself got wrong.
2. **8-bit texture mode**: neither the corpus nor the fuzz ever reached it. The fuzz drew the texpage texture mode as a two-bit value that could only land on 4bpp or direct15, and rectangles (unlike polygons) take their texpage from GP0(E1), so no textured rectangle ever sampled an 8-bit page and the 256-entry CLUT path ran against nothing. The oracle uploads an 8bpp texture page and two CLUT blocks. One block's 256-entry cache load wraps across the VRAM row end, exactly as DuckStation's software backend does. It then asserts literal pixels for raw and white-modulated draws covering both u parities and indexes 128-255, the wrapped cache half, the stale-cache rule (CLUT VRAM writes are only observed after a register change or GP0 0x01 clear-cache), and the polygon texpage quirk. That quirk: a polygon takes its texpage from the second vertex's texcoord word, so a triangle drawn while GP0(E1) says 4bpp must still sample 8bpp from the stream. Corrupting the CLUT wrap or dropping that merge in both engines at once passes every engine-vs-engine compare and fails only the oracle, which proves the coverage closes the shared-bug class for the 8bpp pipeline too.
3. **Semi-transparency blending**: both models scalarized DuckStation's single software-rasterizer implementation verbatim, so a transcription typo shared by both sides is invisible to engine agreement. The oracle asserts backdrop fills plus semi-transparent rectangles in all four texpage transparency modes, textured and untextured, against literal per-channel closed forms of the DuckStation formulas. Textured means raw 15-bit direct, where a texel with bit 15 clear must be written opaque even under a semi command, and one with bit 15 set must blend. The formulas: saturating add, saturating subtract, and backdrop plus foreground/4 for modes 1-3, verified against the formulas over the whole color space. Mode 0 is `floor((f+b)/2)` per channel in the carry-free regime, with untextured results stored bit-15-clear and textured ones bit-15-set. Blending arithmetic was already faithful to DuckStation on both sides, so the phase's own first catch was a test-data bug: 0x02 backdrop fills align their x to 16 pixels, so an 8-pixel backdrop at a non-aligned x moved under the semi rectangle and left part of it blending over stale VRAM. After fixing the geometry, corrupting the mode-0 divisor, the textured blend gate, or the mode-3 masks in both engines at once passes every differential compare and fails only the oracle.
4. **Mask-bit machinery**: the corpus and fuzz only ever compared the GP0(E6) set-mask / check-mask semantics engine-vs-engine. Set-mask draws must OR bit 15 into every written pixel. Check-mask draws must skip pixels whose bit 15 is already set, after reading the backdrop. The 0x02 fill must ignore both mask bits entirely, because DuckStation's FillVRAM takes no mask arguments. VRAM-to-VRAM and CPU-to-VRAM transfers must honor both bits at the destination, because DuckStation passes the GPUSTAT mask bits into CopyVRAM and UpdateVRAM. A semi-transparent draw with check-mask on must skip masked pixels before blending. All of it was already faithful to DuckStation on both sides. The phase's own first casualty was a test bug: a uniform expectation over a region whose two halves legitimately differ. Dropping the set-mask OR or flipping the check-mask polarity in both engines at once passes every differential compare and fails only the oracle, while mutating either side alone fails the differential itself.
5. **VRAM-to-VRAM copy direction**: the corpus only ever copied engine-vs-engine and never with source and destination overlapping. DuckStation's software backend splits oversized copies into chunks (a path it flags as not verified on console). For the simple case it copies in reverse when the source x is left of the destination x, or when the wrapped end-of-span comparison inverts (explicitly marked verified on console). The engines implement this directly with per-pixel wrapping and no chunking, matching DuckStation exactly for the unwrapped-span case real games use for their per-frame 2x2 copies. The oracle uploads column-distinct 15-bit patterns and asserts literal pixels for forward and reverse copies, destructive same-row overlap in both directions (the wrong direction smears the source), the wrapped-end reversal clause (which also flips the corpus's own wrap case to reverse, so dropping it in one engine fails the differential at that case), a row-wrap copy, the self-copy skip when source equals destination without set-mask, and the self-copy with set-mask that must run and set bit 15. The fuzz coordinate ranges were also widened from a 640x480 box to the full 1024x512 VRAM plus wrap margins, which they had never exercised. Dropping the reversal or the wrapped-end clause in both engines at once passes every differential compare and fails only the oracle, while mutating the core alone fails the differential itself.
6. **Line DDA and Gouraud shading arithmetic**: both models scalarize DuckStation's fixed-point interpolators verbatim. Lines use 12-bit RGB steps from `c*4096+2048` with truncating division, polygons use 24-bit determinant steps, and positions use `x*2^32` with a -1024 bias on the line DDA. A shared transcription typo would be invisible. The oracle asserts every pixel of mono and gouraud lines from closed forms derived from the DDA math rather than copied from the engines: the inclusive k+1-pixel span, both fractional-step directions and their exact phases (the x axis carries the -1024 bias so a shallow line doubles up starting immediately, while the unbiased positive y axis rounds its first half-step up), the descending-y bias, the right-to-left swap that also swaps the endpoint colors, per-pixel ramp values (red stepping 0, 21, 43, 64, 85, 106, ...), and a shaded-triangle interior whose determinant divides evenly, so interior colors are the exact affine `floor(0.5 + 7.96875*(x-20) + 6.375*(y-360))`. Building the phase caught two closed-form phase errors in the test itself, not engine bugs. Dropping the position or color rounding bias in both engines at once passes every differential compare and fails only the oracle, while mutating one engine alone fails the differential itself at the corpus's gouraud line.
7. **Texture-window masking math**: the corpus's single tex-window case only ever compared engine-vs-engine. DuckStation decodes GP0(E2) as AND = `~(mask*8)` and OR = `(offset & mask)*8`, applied per texel as `(u & AND) | OR`. This is block arithmetic on 8-texel blocks, which means the offset is ignored entirely when the mask is zero. The oracle makes the sampled coordinate directly observable: a 64x64 raw direct15 texture page whose texel color encodes (u, v) as `u | (v << 6)`, drawn with raw textured rectangles (command bit 24), so every drawn pixel is exactly the texel at the windowed coordinate. It pins identity, mask-only and mask-plus-offset on x, a two-bit mask, mask-only and mask-plus-offset on y, both axes at once, the offset-with-zero-mask-ignored rule, and a raw 4bpp rect proving the window applies before the nibble decode. Building it surfaced a test-data bug of its own: an underfed 4bpp page upload left the transfer pending and ate the next command word, desyncing the stream. The audit also confirmed the core applies the window in two sites, `GPU:texel` and the shadePixel fast path, which must agree and which the phase exercises. Dropping the window or the mask-gate on the offset in both engines at once passes every differential compare and fails only the oracle, while mutating one engine alone fails the differential at the corpus's own tex-window case.
8. **Drawing-area clipping and drawing offsets**: no corpus or fuzz draw ever exercised these, since everything used the full area and offset zero. The oracle pins GP0(E3)/GP0(E4) area clipping with DuckStation's per-pixel all-four-edges rectangle clip (the software rasterizer skips when x is left of the area's left edge or right of its right edge, and likewise for y), GP0(E5) offsets applied to the sx11-wrapped vertex position and re-wrapped for rectangles, degenerate (left > right) areas drawing nothing, the VRAM right-edge clamp, the -1 coordinate wrap landing at 1 under a +2 offset, and a flat triangle under an offset. Each checked box is cleared first with a 0x02 fill, which doubles as a live probe of a real hardware rule: the fill ignores the drawing offset, both mask bits, and the clip, because DuckStation's FillVRAM takes none of those. Pre-clears are therefore exact regardless of state. Building the phase surfaced three geometry mistakes in the test itself (a check box that overlapped the mask oracle's row, a box that indexed past the VRAM row end into the 8bpp fixture, and a mis-derived offset triangle edge). The engines were already faithful on every case. Dropping the offset or the left/top clip in both engines at once passes every differential compare and fails only the oracle, while mutating the core alone fails the differential itself.
9. **GPUSTAT and GPUREAD encoding**: the harness compares these engine-vs-engine after every command but never against a literal word, so a bit-mapping bug shared by both models is invisible. The core's GP1 0x08 mapping was fixed in an earlier round only because the reference disagreed. DuckStation's GPUSTATReg bitfield is the ground truth: bits 0-10 mirror the draw mode with bit 15 mirroring the texture-disable bit (gated by GP1 0x09), GP0(E6) SetMaskBit writes bits 11-12, GP1 0x08 maps its fields onto bits 14 and 16-22, GP1 0x03 display-disable writes bit 23, GP1 0x04 writes the direction to bits 29-30, and reset restores `0x14802000`. The oracle pins the raw word in both engines after reset, display enable/disable, all four DMA directions, six display-mode parameters, the E1 draw-mode mirror under both texture-disable gates, and all four mask-bit values. It pins the GP1(0x10) info-2/3/4/5 GPUREAD latches (texture-window masks, drawing area, signed 11-bit offsets) against literal readbacks. It pins the core-only composed read (bits 25-28, a scalarization of DuckStation's UpdateDMARequest/UpdateGPUIdle) through an idle/direction sweep and mid-transfer while a VRAM-to-CPU copy is in flight, including the deferred-drain quirk where pending draw ticks keep the idle bit clear until `step()` runs, and the core's per-frame bit-31 toggle. The reference's step is a documented stub. Neither engine ever asserts bit 24 (interrupt request), which DuckStation raises from its CRTC interrupt path and the models leave out of scope, so GP1 0x02 ack is pinned as the no-op it is. Building the phase surfaced four expectation bugs in the test itself: GP1 reset is word `0x00000000` while `0x01000000` is clear-FIFO; pal plus interlace OR to `0x14D02000`, not `0x14902000`; draw-mode bits 0-10 OR to `0x148027FF`; and a phantom bit 16 in the unmasked draw-mode value. The engines were faithful on every case. Dropping the texture-disable mirror or the reverse-flag mapping in both engines at once passes every differential compare and fails only the oracle, while corrupting the display-disable bit in the core alone fails the differential itself.
10. **Textured-polygon uv interpolation**: the corpus's textured triangles and quads only ever compared engine-vs-engine. Both models scalarize DuckStation's determinant-based attribute steps (`truncate(det*4096/det) << 12`, a per-pixel texel value in 24-bit fixed point with a +2048 half-texel bias) for u/v exactly as for colors, and the sampled texel is `rshift(uv, 24)` of that accumulator. A shared typo in the uv steps would sample every textured 3D model from the wrong texel while every gate stayed green. The oracle draws raw (unmodulated) textured polygons against a direct15 page whose texel color encodes (u, v), so every drawn pixel reports the interpolated coordinate. The geometries are chosen so each uv gradient is exactly one texel per pixel or zero, which leaves the fixed-point accumulation residue-free and makes the sampled coordinate the exact affine of the pixel position. It pins a triangle sampling `u = x-40, v = y-450`, a mirror triangle with u decreasing rightward, a rotated triangle swapping the axes so the dvdx gradient is exercised, and a quad whose two split triangles must agree on the shared interior. Each draw follows the real wire format: first color in the command word, per-vertex texcoords, and the texture page merged from the second vertex's texcoord word under DuckStation's polygon_texpage_mask `0x9FF`. Building the phase surfaced one genuine geometry fact, not an engine bug. DuckStation splits quads into triangles (v0,v1,v2) plus (v2,v1,v3), which tiles the quad only when the shared v1-v2 edge is a diagonal. Quad corners sent top-left, top-right, bottom-right, bottom-left therefore leave a wedge uncovered in the rasterizer, and the oracle's own first quad case drew it exactly that way. Zeroing the dvdy or dvdx step in both engines at once passes every differential compare and fails only the oracle, while zeroing dudx in the core alone fails the differential itself at the corpus's own textured-polygon case.
11. **Line DDA drawing-area clip**: no corpus case, fuzz draw, or oracle ran a line whose DDA crosses the drawing-area boundary or whose sx11 endpoint is negative, so the per-pixel area filter DuckStation applies in DrawLine had no literal owners. The filter skips when x is left of the area's left edge or right of its right edge, or when y is outside the vertical span. The expectations reuse the derived position closed forms and apply the area predicate, so each checked pixel must equal the flat color exactly when its position passes the filter and stay zero otherwise. The cases: a horizontal entering from the left of the area, a vertical whose top half is above the area (whose p0.x >= p1.x swap starts the DDA at the low endpoint), a line whose sx11 endpoint is -40 (`0x7D8`) entering from off-VRAM through the signed DDA, a horizontal clipped by the right edge, and a descending shallow line clipped by the bottom edge (rows 154-156 filtered away while `y = 156 - floor((i+1)/2)` continues to 150). The engines were faithful on every case, and the phase passed on the first run. Removing the left or bottom clip in both engines at once passes every differential compare and fails only the oracle, while removing the right clip in the core alone fails the differential's own VRAM compare at the first out-of-area pixel.
12. **Terminated polylines (GP0 0x48-0x5F)**: the corpus's last never-literal-pinned primitive. Its segments reuse the line DDA, but three things had no literal owners: the variable-length command's wire parsing (vertex-led: the first vertex follows the command word and carries the command's flat color, and later gouraud vertices arrive as (color, xy) pairs), its terminator recognition (`(word & 0xF000F000) == 0x50005000`), and its per-segment chaining (every consecutive vertex pair rasterizes as a full line, so consecutive segments share the join pixel). The oracle pins a mono three-vertex L whose corner pixel must be drawn by both segments, a gouraud three-vertex L whose horizontal ramps red to blue and whose vertical (running downward from the high vertex after the p0.x >= p1.x swap) ramps blue to green, and a short mono polyline whose terminator lands immediately after the second vertex, exercising the reference's swallowed-terminator path. The engines were faithful on every case. Drawing only the first segment, or flattening the gouraud per-vertex colors to the command color, in both engines at once passes every differential compare and fails only the oracle. Drawing only the first segment in the core alone fails the differential's own VRAM compare at the corpus's polyline mono case.
13. **Modeled command time**: the differential never compares timing, because the reference models none at all. Every tick formula was previously verified only by reading the code, and an audit against DuckStation's gpu.cpp found three real divergences, all invisible to every gate. The core charged the 16 setup ticks to single lines too (DuckStation's HandleRenderLineCommand charges only the per-line DDA ticks; only HandleRenderPolyLineCommand pays 16 once). Textured rectangles paid a flat one-width-per-row cache overhead regardless of texture mode (DuckStation's AddDrawRectangleTicks overhead is mode-dependent: 4bpp adds one width per row, while 8bpp and direct15 add one width only while the row stays at or under 128 and the area fits the cache, then switch to a reload term once the width exceeds 128 or the area exceeds 2048 or 1024 texels). The rectangle tick box clamped its endpoints to the drawing area, so a rect fully outside still cost a clamped row (DuckStation intersects the rect with the area, so a disjoint rect is empty and costs zero beyond the setup). The core now implements all three the DuckStation way, and the oracle freezes the corrected contract with literal pendingCycles deltas per command class. Config words cost 1 each. A fill costs `46 + ((w/8) + 9)*h` with w pre-rounded up to 16. Single lines cost `max(w,h)` with no setup. Polylines cost 16 plus per-segment line ticks. Rectangles cost 16 plus per-row cost times the intersected height. Polygons use the setup table `{{46,226},{334,496}}` and `{{82,262},{370,532}}` plus shoelace area/2 (doubled when textured, plus 50% when semi-transparent or mask-checking, and skipped when the polygon is culled too large). VRAM-to-VRAM costs `width*height*2` even when the copy is skipped. The 16/256 CLUT reloads happen on the first palette- or 8bpp-changing textured draw. Any tick mutation in the core passes the entire differential battery, so this oracle is the only gate on the timing model. Reintroducing the line setup overcharge, the flat textured overhead, or the endpoint clamp each passes every differential compare and fails only at a named tick pin.
14. **CPU/VRAM transfer geometry**: every earlier phase exercised transfers only engine-vs-engine. CPU-to-VRAM uploads and VRAM-to-CPU readouts carry no literal expectations anywhere, and the harness itself had slipped two transfer bugs into its own test data over earlier rounds (an underfed 4bpp upload whose pending transfer silently ate the next command, and a half-word count mistake). The oracle pins literal VRAM pixels for uploads: each 32-bit data word carries two 16-bit pixels low half first at consecutive positions, an odd starting column must not re-align the halves, a word crossing the right VRAM edge wraps within the same row (VRAM is a 1024-wide ring per row, matching DuckStation's `(x + col) % 1024`), and rows wrap with `% 512`. It pins literal returned words for readouts, including a read whose cursor crosses the row ring, and pins the 2 modeled ticks per transferred word on both the write and read sides. The abort case found a real divergence between the models. The core streams c2v writes straight into VRAM, so a GP1 soft reset mid-upload leaves the pixels already received in place (DuckStation's FinishVRAMWrite flushes the partial write on reset and on clear-fifo), while the reference buffered the whole upload and dropped it on abort. The reference now flushes the partial write exactly like DuckStation (full rows, then the partial last row, with the mask bits applied), and the oracle pins the abort: the four partially uploaded pixels stay, the GPU returns to command parsing, and the next word parses as a command. Swapping the c2v half-word order, swapping the v2c read packing, or dropping the row-ring wrap in both engines at once each passes every differential compare and fails only a literal oracle. The c2v swap corrupts the dither oracle's uploaded texture first, the wrap drop corrupts the v2v oracle's wrapped-end fixture first, and the read swap dies at the transfer oracle's first literal read word.
15. **Textured modulation multiply**: the one place a texture color and a flat or interpolated light color combine. Every earlier modulated draw ran at white, whose pins provably cannot see the crop rule because `(t*255) >> 7` equals `(t*31) >> 4` for every t, or compared engine-vs-engine. The audited ground truth is DuckStation's ShadePixel, which modulates `lut[(t5*c8) >> 4]` (net `min(31, floor(t5*c8/128))`) with the interpolated 8-bit color at full precision, unless the optional gpu_modulation_crop setting (default off) first quantizes it to 5 bits. The oracle draws a constant direct15 texture page with texel channels (18, 1, 31) and pins three flat textured rectangles: at the multiply's identity point (color 128 must reproduce the texel exactly, so any scale slip dies there), at a crop-discriminating color (79 outputs red 11 while the crop rule gives 10), and at white (the clip to 31 the ceiling enforces). It also draws a shaded textured triangle reusing the same interior whose interpolated red is the closed form `floor(0.5 + 7.96875*(x-20) + 6.375*(y-360))` with green and blue constant, so pixels whose red lands on 7 mod 8 freeze the crop-off semantics with literals. The engines were faithful to the DuckStation default on every case. Quantizing the color to 5 bits in both engines at once passes every differential compare and fails only the oracle at the flat rect (red 11 demanded, 10 drawn). Slipping the multiply scale in both engines fails the dither oracle's own white pin first, also oracle-only. Quantizing the color in the core alone fails the differential itself at the corpus's quad shaded tex case, a pixel off by exactly one, with one-sided sensitivity intact.
16. **Semi-transparent polygons**: the surface every translucent 3D object runs but the rectangle-only blend oracle never reached. A mono textured semi triangle whose texel has bit 15 clear must be written opaque (never blended) even under a semi command. Bit-15 texels must blend through the modulated foreground under abr 2 and abr 0 with odd sums, so `floor((f+b)/2)` is distinguishable from rounding. A raw textured semi triangle whose stream texpage says abr 2 while GP0(E1) says abr 1 proves a polygon's transparency mode rides its own texcoord word, the 0x9FF merge no rectangle can exercise. A shaded untextured semi triangle blends the interpolated color under abr 1 and stores it bit-15 clear, exactly DuckStation's rule that non-textured transparent polygons don't set bit 15 but are treated as transparent. The engines were faithful on every case. Removing the texel bit-15 gate, or keeping bit 15 on untextured blend results, in both engines at once each passes every differential compare and fails only a literal pin (the blend oracle's opaque-texel rect for the gate, its untextured abr-0 rect for the stored bit). Removing the gate in the core alone fails the differential's own compare during the blend oracle's feeds.

A divergence names the phase, command, and word and exits nonzero.
